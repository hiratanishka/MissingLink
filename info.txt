## PROJECT OVERVIEW

MissingLink is a missing-person record search system developed using Python, Streamlit and Data Structures and Algorithms.

Users can upload Excel or CSV datasets, search for similar records, add new records and explore possible connections between reports.

The system suggests possible matches. It does not confirm a person's identity.

## DATA STRUCTURES AND ALGORITHMS

| Algorithm | Purpose |
|---|---|
| Hash Map | Location-based record lookup |
| Linear Search | Compare selected records |
| Min Heap | Select Top 10 matches |
| Merge Sort | Sort all matching records |
| Union-Find | Create possible related groups |

## TIME COMPLEXITY

- Hash Map construction: O(n)
- Hash Map lookup: O(1) average for accessing a location's list, excluding the cost of processing its records
- Linear Search: O(n) record checks, assuming bounded comparison work
- Min Heap: O(n log k) for selecting Top k
- Merge Sort: O(n log n)
- Union-Find: Nearly O(1) amortized per operation using path compression and union by rank

The complete search time also depends on the number of candidate records and the amount of information being compared.

## DATA PRIVACY

- The original newspaper dataset is kept private.
- Real records are not included in the public repository.
- Fictional records are used for demonstrations and tests.
- Users can upload their own CSV or Excel datasets.
- Local saved copies are stored on the computer running the application.
- Possible matches must be verified by humans.

## PROJECT LIMITATIONS

- Similarity scores are based on manually selected rules.
- Matching details do not prove that two reports belong to the same person.
- Missing or incorrect information can affect results.
- Union-Find groups may include indirectly connected reports.
- Performance depends on dataset size, record content and hardware.
